# 👥 Посібник з командної роботи над проектом

## 🔄 Процес внесення змін

### 1. Оновлення локального репозиторію

Перед початком роботи завжди синхронізуйте свою копію:

```bash
git checkout develop
git pull origin develop
```

### 2. Створення нової гілки для роботи

```bash
git checkout -b feature/ваш-новий-файл
```

Назви гілок повинні відповідати шаблону:

- `feature/назва-функції` - для нових функцій
- `fix/проблема-яку-виправляєте` - для виправлень
- `docs/що-документуєте` - для документації

### 3. Внесення та комміт змін

```bash
git add .
git commit -m "Зрозумілий опис ваших змін"
```

Правила гарних комміт-повідомлень:

- Пишіть конкретно, що зроблено (наприклад, "Додано функцію нормалізації даних")
- Використовуйте дієслова в минулому часі
- Обмежуйте заголовок 50 символами
- За потреби додавайте детальніший опис, аби розуміння команди було синхронізоване

### 4. Відправлення змін на GitHub

```bash
git push origin feature/ваша-нова-функція
```

### 5. Створення Pull Request

1. Відкрийте GitHub
2. Перейдіть на вкладку "Pull requests"
3. Натисніть "New pull request"
4. Виберіть свою гілку та гілку `develop` як базу
5. Заповніть детальний опис змін

### 6. Код-ревʼю та обговорення

Дочекайтеся перегляду від колег. Будьте готові:

- Відповідати на запитання
- Вносити вдосконалення за запитами

## 📂 Структура проекту

Дотримуйтесь структури директорій:

- `data/` - зберігайте тут набори даних
- `scripts/` - розміщуйте тут R-скрипти
- `results/` - зберігайте тут результати аналізу
- `docs/` - документація по проєкту

## 📝 Стандарти коду

- Додавайте коментарі для пояснення неочевидної логіки
- Використовуйте змістовні назви змінних
- Документуйте функції (вхідні параметри, повернені значення, мету), можна використовувати autodoc

## ❓ Часті запитання

**Q: Що робити, якщо я випадково закомітив у неправильну гілку?**
A: Використайте `git reset` для скасування коміту, перейдіть до правильної гілки, та знову внесіть зміни.

**Q: Як вирішувати конфлікти злиття?**
A: GitHub виділить конфліктуючі рядки. Вам потрібно вибрати, які зміни зберегти, а потім виконати `git add` та `git commit`.
